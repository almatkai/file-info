# Host integration and lifecycle

The source manifest uses schema 3, external `execution: process`, protocol 1, SDK 0.1.1 and canonical `com.tezbar.native.file-info`. It replaces only `com.tezbar.file-info` and `raycast.file-info`, with both `show-file-info` and `clear-file-metadata`. The pinned Recommended row is retained in `fixtures/registry-file-info.json`. Nothing activates a root workflow or writes the host registry/catalog/acquisition policy.

The parent-owned host pin is `ea100cee3f69711de12485ba061950c5fc65258f`. One necessary generic prerequisite remains UNAPPLIED: `patches/0001-bounded-complete-file-selection.patch`. The current producer slices Finder/Explorer results to 128 before reporting them, filters entries with is_file, and buffers child output before checking its length. The patch preserves the entire selection snapshot, including explicitly selected directories for read-only info, rejects over-capacity/non-absolute results explicitly and bounds both pipes during capture. It was applied/tested only on `.qa` copies. The actual Finder script's 129→128 behavior and patched 129→129 behavior are executed in a closed VM; the actual native parser then rejects >128. Actual native producer bodies compile/run against in-memory subprocess fakes. Empty/nonempty directory-first snapshots preserve the original ordering with a second selected ordinary file; the original producer drops the folder, while the unapplied patched producer admits it. Clear-specific directory rejection stays in the command. PowerShell execution itself remains Windows QA.

Required reverse services are precisely `selection.read`, `clipboard.write`, `shell.reveal`, `shell.openWithApp`, `apps.list`, `dialog.confirm`. Selection is requested once with `{kind:"files"}` and must return an absolute STRING array. Confirmation accepts only closed `{response:0|1}`. Clipboard/reveal/open-with accept only closed `{ok:true,message?:string}`. Null, booleans, missing/false ok, unknown keys and contradictory result objects are rejected. The pinned actual clipboard and reveal producers return `{ok:true}`; confirmation returns the numeric response object. Clipboard read, paste, visibility, settings and shell.open are unused, so their differing contracts are not guessed.

All host effects consume current action IDs synchronously outside SDK staged state, before await. Exact frozen text/path/app parameters survive cancellation or malformed ACKs. No selection or file information is reacquired on retry. A fresh visible Retry action warns about possible duplication; no automatic replay exists. Acknowledged actions regenerate normal IDs for deliberate repetition. Consumed/stale IDs issue no reverse call. They return a structured SDK error rather than action `unchanged`, because the pinned action-result renderer expects view/no-view/error and would otherwise replace its root with undefined fields. An old action following an unknown outcome can reveal the recovery view without performing the retry. Open With's unknown-outcome screen never binds Back/Escape to a retry.

The UI's query belongs to the actual local List renderer. No root searchText prop or server-search flag is emitted. Refresh returns cached file information and cannot overwrite A/B/A or intermediate query edits. File reads only populate initial-open state. SDK generation/session fences suppress late responses.

An open guard releases cancelled opens even when the SDK omits dispose. A cancellation probe is polled only during ordinary request-bound pruning, with no background task/thread. Per-process spent IDs are capped at 4096 and never recycled; live adapter sessions are capped at 128. Recent reports retain the same checkpoint object across retirement, so a synchronous commit racing cancellation still updates its known outcome. Unknown/preparing and not-started items remain explicit. History is memory-only and bounded; process crashes lose it. There is no durable exactly-once claim.

Host lifecycle responsibilities remain the pinned SDK contract: unique session IDs per process generation, dispose no-view sessions, no action replay, bounded reverse calls, termination of helper trees, stdout framing at 16 MiB, idle shutdown without extension leases, and canonical identity/artifact checks. Both manifest desktop verification states deliberately remain not-run. The development ZIP is for review and extracted-process QA; it is not a published release or installed extension.
